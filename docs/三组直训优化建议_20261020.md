# 三组直训优化建议：保留全量标签，调整类别损失与教师目标

> 后续方向调整（2026-10-20）：用户将核心问题明确为“已有半量融合的互补收益能否迁移到学生”。本文件的 80/20 教师辅助标签平滑候选暂缓，不作为该问题的执行方案；现有缓存即可构造直接融合目标，见 [现有缓存融合蒸馏](现有缓存融合蒸馏_20261020.md)。没有启动本候选训练。

日期：2026-10-20。状态：**具体候选方案，尚未训练**。损失原型、输入审计和 CPU 梯度检查已完成；训练控制器尚未接入。此文件不替换当前已完成实验的冻结配置，也不授权启动 GPU 作业。

## 推荐做什么

保留从官方底座和同一未训练 LoRA 开始的 CE/KD/WCE 三组结构，恢复全部 31,339 条标签数据。三组共同采用温和的类别加权；KD 改成真实标签主导、教师提供非正确类分布的软目标。缓存重复使用，不补 DeepSeek 请求，不使用旧学生 S 或 S 参考 KL。

这次希望解决的具体问题：现有直训对 S/C 类的学习不足，原始教师软概率未稳定胜过同样本硬标签加权；仅提高缓存覆盖比例会丢掉大量独立标签信息。以下修改是明确可检验的假设，不是已证明有效的新配方。

## 1. 全部标签用于三组训练

合并 `data/sft/pilot_train.jsonl` 的 20,941 条与 `data/posttraining/train.jsonl` 的 10,398 条，每轮全部样本各出现一次，三组顺序一致。不用三遍小数据冒充一遍大数据。

新增教师请求为 0。10,387 条有效教师缓存仅对应原缓存子集，另外 20,941 条依然只有真实标签；这是有意保留的部分教师监督，不声称全数据都有教师概率。

## 2. 三组共同加强少数类别的真实标签损失

使用训练集类别数的平方根倒数作为权重，再归一到全训练样本的平均权重为 1：

```text
raw_w[k] = 1 / sqrt(n[k])
w[k] = raw_w[k] / sum_j(n[j] * raw_w[j] / N)
```

| 类别 | 全量样本数 | 权重 |
|---|---:|---:|
| E | 14,105 | 0.7953 |
| S | 10,414 | 0.9255 |
| C | 1,393 | 2.5306 |
| I | 5,427 | 1.2821 |

C 相对 E 的单样本权重约为 3.18 倍。平方根方案比完整逆频率加权温和，避免把极少数类的标签噪声放大到约十倍；但仍可能影响 accuracy，必须与 Macro-F1 一起报告。权重只由训练类别数计算，不用 F 调权重。每批仍除以实际样本数，不再除以批内权重和。

## 3. KD 改为教师辅助的标签平滑

设 `y` 是真实类别的 one-hot，`t` 是缓存教师四类概率。先在非正确类中归一化教师概率：

```text
r[y] = 0
r[k != y] = t[k] / sum_{j != y} t[j]
q = 0.8*y + 0.2*r
```

如果教师在非正确类上的概率总和为零，则在三个非正确类上均匀分配。`v=1` 表示教师缓存有效，不再要求原始教师 argmax 正确。

| 组 | 本候选逐样本目标 |
|---|---|
| CE | `w[y] * CE(y,p)` |
| KD | `w[y] * [CE(y,p) + v*KL(q||p)]` |
| WCE | `w[y] * [CE(y,p) + v*CE(y,p)]` |

无缓存或缓存失败的样本三组都只有加权真实标签 CE。所有额外项系数为 1，不再使用旧正确性门控系数 1.8999。

对有效缓存样本，KD 的参数梯度等价于权重 `2*w[y]`、目标 `(y+q)/2` 的交叉熵：**真实类占 90%，教师只分配其余 10%。** 教师即使把 argmax 判错，也不会把错误类别变成训练主目标。这里的 90% 是等价目标中的概率质量，不是实际梯度贡献占比。

这不是继续蒸馏原始教师的完整分布，而是明确改变为教师辅助标签平滑。它限制错误软目标对真实标签的影响，也丢弃了教师对正确类的置信度信息；是否有利需要实际验证。教师在错误类别之间的相对概率也可能无用或有害。

有效缓存中参与软目标的 C 类样本从旧门控的 195 条变为 516 条；整体从 5,467 条变为 10,387 条。**这些都是已有缓存，并非新增教师样本。** 未乘类别权重时，旧额外系数总和为 `5467*(10387/5467)=10387`，新方案也为 10,387；改变的是分配范围及目标内容，不是简单加倍总系数。加上类别权重后，应另报告实际加权总量。

WCE 使用相同有效缓存 mask、相同样本权重和额外系数，只把软目标换成真实标签，因此仍能控制额外训练权重。名称虽然仍叫 CE/KD/WCE，其目标和 mask 已发生版本变化，不能与历史对象混同。KD−WCE 只能检验这种软目标相对硬目标的作用；没有均匀标签平滑对照，不能进一步宣称收益一定来自教师独有知识。

0.2 是拟议的初始非正确类质量，不是调参得到的最优值。它让组合目标保留 90% 真实类别，给候选一个明确、有限的软监督强度。本轮只验证这一组预先写明的值，不隐式展开参数搜索或增加模型训练组。

## 4. 训练时长由 tune 反馈，不预设 975 最好

拟议控制器如下（尚未接入训练代码）：

- 保留峰值 lr=1e-4，以前 98 步 warmup；之后维持当前 lr，根据验证表现衰减。
- 每 245 步评估完整 tune，相当于全量数据四分之一轮。三组各自按同一规则执行。
- 相对调度器记录的最好 tune Macro-F1，连续两次提升不足 0.002（0.2 pp），学习率减半，最低 1e-5。降率后清零降率等待计数，提前停止等待计数不清零。
- 至少完成 980 步后，连续四次没有上述幅度的提升则停止该组。每组最多三轮 / 2,940 步，仅作为算力上限；达到上限不代表收敛，也不代表最后一步最好。
- checkpoint 始终按实际 tune Macro-F1 最高、平局 nDCG@10、再平局更早步选择。调度器的 0.2 pp 阈值不用于抹掉 checkpoint 的更小改善。
- 每组只初始化一次优化器，不在 epoch 边界重置。三组初始化权重和首次训练前 RNG 相同，后续各自保存/恢复 RNG。

各组使用同一自适应规则，实际学习率轨迹和停止步数可以不同，需如实报告。因此主结论是同一训练控制规则下各组最优模型的比较；另报告三组均已保存的共同评估位置，不能把不同曝光量写成相同。

98、245、0.2 pp、等待两次/四次与三轮上限都是透明的工程初值，不是由现有结果唯一推导出的最优超参数。它们的作用是把调度和停止接到 tune 反馈，而不是再猜一个“最佳总步数”。

## 5. 先统一评测设置

正式 eval batch 固定为 8，固定输入顺序、分词、精度和模型版本。训练前应对同一 B0、同一小样本分别用 batch 8/32 复测，并记录实际概率漂移；若要直接比较旧模型，需在同一正式设置下复测旧 checkpoint。旧两轮 B0 已有 732 条 argmax 差异，不能未经复测就认为跨轮推理完全等价。

先在 CPU 完成目标/梯度和输入检查，再做小样本 GPU 的 batch、初始化/RNG、尾批和恢复检查。检查通过后才进入这三个组的正式训练。本建议没有运行这些 GPU 检查或正式训练。

tune 用于选点与调度；gate/F 在配置和 checkpoint 固定后统一报告，不用它们挑权重或找“显著”的步数。它们已被多轮开发查看，新结果不能冒称新的独立测试结论。
