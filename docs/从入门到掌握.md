# ESCI：从入门到掌握

当前唯一路径：`python src/train.py sft` 将官方底座训练成 S；`python src/train.py fusion` 从固定 S 检查点启动三组续训。前者分发到 `sft.main()`，后者分发到 `fusion.main()`；两阶段共用模型前向与指标实现。

第一阶段使用 pilot_train 的 20,941 条 / 1,024 查询，seed=20260928，2 epochs；查询内 group_size=2，每次更新 16 groups，每次前向 1 group，lr=1e-4，warmup=5%，max_length=512。`sft.verify_inputs()` 检查输入，`sft.train_sft()` 调用 `common.epoch_groups()` 与 `modeling.RelevanceModel.forward/save` 完成训练。下文详细解释第二阶段。

这个项目让一个小模型判断：用户搜索某件商品时，搜索结果里的每个商品与需求是什么关系。我们先用真实标签训练出一个能做这项任务的模型，再把它与 DeepSeek 的预测结合起来。已有实验发现，这种组合能提高成绩，于是有了本轮的问题：**能否让一个小模型学会组合系统的一部分能力，部署时只运行这个小模型？**

本文按这个过程解释 2026-10-21 已完成的融合蒸馏实验：先认识任务和模型，再看训练用的参考答案从哪里来、三组实验如何比较，最后解释损失、结果和代码。

## 1. 模型要判断什么

一条样本由一个购物查询和一个候选商品组成。模型读取查询、商品标题和品牌，判断两者属于哪一种关系：

| 标签          | 含义                   | 以搜索“无线鼠标”为例 |
| ------------- | ---------------------- | ---------------------- |
| E：Exact      | 满足主要意图和约束     | 无线鼠标               |
| S：Substitute | 不完全匹配，但可以替代 | 有线鼠标               |
| C：Complement | 与目标商品配套使用     | 鼠标垫                 |
| I：Irrelevant | 与需求无关             | 水杯                   |

这些是用于解释概念的简化例子。实际训练使用数据集已有的类别标注，称为**真实标签**，记作 `y`。标签放在训练答案里；模型输入是查询、标题和品牌。

模型会为四个类别分别给出一个概率。下文所有概率都按 **E、S、C、I** 的顺序排列，例如：

|    E |    S |    C |    I |
| ---: | ---: | ---: | ---: |
| 0.40 | 0.35 | 0.15 | 0.10 |

四个数相加为 1，这就是“四类概率分布”。这次预测最倾向 E，但也给 S 留了较高概率。分类时取概率最大的类别，因此输出 E。

同一个查询下还需要给多个候选商品排序。本项目把四类概率换算成一个相关性分数：

`排序分数 = p(E) + 0.1 × p(S) + 0.01 × p(C)`

这里的 `p(E)` 就是模型给 E 的概率。上面这条预测的分数是 `0.40 + 0.1 × 0.35 + 0.01 × 0.15 = 0.4365`。候选商品按这个分数从高到低排列。

## 2. 从原模型到融合系统，再到新学生

项目使用的底座是 Qwen3-0.6B。第一阶段在 20,941 条带标签的 ESCI 样本上训练，让它学会这项四分类任务。这种拿任务输入和正确答案来训练模型的做法，叫监督微调，简称 **SFT**。

训练采用 **LoRA**：保留底座原有权重，只训练附加在网络中的一小部分参数。这部分参数保存为一个 adapter。第一阶段得到的模型在项目中命名为 **S**；下面称它为“原模型 S”，以便与类别 S（Substitute）区分。

接下来，项目让原模型 S 和 DeepSeek 分别对同一条样本给出四类概率，并在一部分样本上把两者的概率取平均。这样形成了一个**融合系统**。两个模型对类别的判断不同，取平均后，最后选出的类别和商品排序都可能变化。已有融合实验观察到了成绩提升。

融合系统运行时需要原模型和教师两份预测。本轮希望把这种组合后的判断教给一个小模型：训练时让小模型参考融合概率，训练完由小模型独立预测。这就是这里的**融合蒸馏**；提供参考输出的一方叫教师，接受训练的模型叫学生。

本轮涉及的对象及其分工如下：

| 对象          | 在本轮中的作用                                               |
| ------------- | ------------------------------------------------------------ |
| 原模型 S      | 提供已经保存的四类预测概率，同时提供三组学生的初始 LoRA 参数 |
| DeepSeek 教师 | 提供以前已经采集并保存的四类概率                             |
| 融合系统      | 按固定规则组合上述两份概率，生成给学生学习的参考概率         |
| 三组新学生    | 各自加载原模型 S 的同一份初始参数，再按各组训练方法更新      |

因此，原模型 S 的预测和新学生的预测需要分开理解：前者已经存入文件，作为固定参考；后者随着训练发生变化。三组学生分别训练，各自产生一个最终模型。

## 3. 学生要参考的四个概率从哪里来

先给两份已有预测起名字：原模型 S 的概率记作 `p_S`，DeepSeek 的概率记作 `p_T`。本轮训练集有 10,398 条样本，每条都有 `p_S`，其中 10,387 条有有效的 `p_T`。

融合规则先看原模型 S 对每条样本有多确定。这里把四个概率中的最大值 `max(p_S)` 当作置信度，再把全部训练样本按这个值从低到高排序，选出前一半，共 5,199 条。这样把教师参与的范围集中在原模型最拿不准的样本上。**选出哪些样本使用教师预测，这一步叫路由。**

对选中的样本，如果教师概率有效，就把 `p_S` 和 `p_T` 逐类取平均；其他样本直接使用 `p_S`。得到的四个参考概率统一记作 **`q`**：

| 样本情况               | 给学生的参考概率 `q` |
| ---------------------- | ---------------------- |
| 被选中，且教师概率有效 | `(p_S + p_T) / 2`    |
| 其余样本               | `p_S`                |

下面用一条假设被选中、真实标签为 E 的样本说明。**表中的概率是教学示例。**

| 概率来源       |    E |     S |    C |     I |
| -------------- | ---: | ----: | ---: | ----: |
| 原模型 `p_S` | 0.40 |  0.35 | 0.15 |  0.10 |
| 教师 `p_T`   | 0.80 |  0.10 | 0.05 |  0.05 |
| 融合后 `q`   | 0.60 | 0.225 | 0.10 | 0.075 |

这条样本有两种形式的训练参考。真实标签只给出一个类别：“E”，叫**硬标签**；融合概率给出四个数：“E 为 0.60，S 为 0.225，C 为 0.10，I 为 0.075”，叫**软标签**或**软目标**。它保留了模型对各类别的相对倾向。

**“目标分布”指的就是学生要学习的这四个参考概率。** 在原模型约束组里，它是 `p_S`；在融合蒸馏组里，它是 `q`。“目标”说明它被用作学习参照，这些数本身仍然来自模型预测，可能与真实标签有分歧，所以训练时还会同时使用真实标签。

实际选中的 5,199 条里，有 4 条缺少有效教师概率。因此，5,195 条的 `q` 来自两模型平均，剩下 5,203 条的 `q` 来自原模型 S。**10,398 条样本都有一份 `q`，也都用于融合蒸馏。** “半量”说的是约一半样本引入教师预测。

这里的回退值明确是 **`p_S`：训练开始前的原模型 S 的缓存概率**。即使某条未被路由的样本有教师缓存，融合参考仍取 `p_S`。因此，FUSION_KD 在这 5,203 条样本上的监督规则与 REF_KD 相同；两组的参考概率差别来自那 5,195 条实际引入教师的样本。

“监督规则相同”具体指：对这条样本，两组都使用同一个真实标签 `y`、同一份固定参考 `p_S`，按 `(CE + KL) / 2` 计算损失。两个学生各自的当前预测仍可能不同，因为它们在其他样本上接受了不同的监督，参数已经沿不同路径更新。因此，相同的参考答案和损失规则，可以产生不同的损失数值、梯度及最终预测。

这些参考概率在训练开始前就计算并保存好了。之后每次读到同一条样本，都读取同一份参考概率；本轮复用已有缓存，新增教师请求数为 0。

## 4. 为什么训练三组学生

本轮首先要回答：融合蒸馏能否比单纯使用真实标签续训取得更好的效果？CE_CONT 和 FUSION_KD 就对应这项比较。随后再追问：融合参考中加入教师概率，是否比只使用原模型概率更有帮助？为回答第二个问题，实验增加 REF_KD 这个对照组。

三组都从同一份原模型 S 的 LoRA 参数出发，使用相同的 10,398 条训练样本。每组重新建立优化器，并采用相同的随机种子、数据顺序和训练预算。它们的主要区别是每条样本上的学习要求：

| 组名                          | 学习要求                                       | 用它观察什么                   |
| ----------------------------- | ---------------------------------------------- | ------------------------------ |
| **CE_CONT：标签续训**   | 根据真实标签提高正确类别的概率                 | 继续做任务训练的效果           |
| **REF_KD：原模型约束对照**  | 既学习真实标签，也让四类预测接近原模型 `p_S` | 移除教师、保留原模型软目标的消融对照 |
| **FUSION_KD：融合蒸馏** | 既学习真实标签，也让四类预测接近融合概率 `q` | 把融合系统的判断教给学生的效果 |

REF_KD 可以直接从融合方法中得到：**移除教师的参与，让全部样本的参考概率回到 `p_S`，其余损失结构和训练设置保持一致。** 这种拿掉方法中的一个组成部分、观察结果如何变化的做法，叫消融实验。因此 REF_KD 是融合蒸馏的“去教师消融对照”。它使用训练开始前原模型 S 的固定概率，损失中的 KL 会牵制学生偏离这份参考。

因此，**FUSION_KD 与 REF_KD 的比较最直接回答：把原模型概率换成融合概率，效果如何？** FUSION_KD 与 CE_CONT 则比较整套融合蒸馏方法和单纯标签续训。训练好的 FUSION_KD 再与原模型 S 比较，可以看出它相对共同起点进步了多少。

## 5. 把学习要求写成损失

损失是训练时要尽量减小的数，用来把上一节的学习要求变成参数更新依据。这里用 `p` 表示**正在训练的学生当前输出的四类概率**；`y` 是真实类别，`p_S` 和 `q` 是上一节介绍的固定参考概率。

### 5.1 交叉熵：提高真实类别的概率

交叉熵简称 **CE**。对一条真实类别为 `y` 的样本，它是：

$$
\mathrm{CE}(y,p) = -\log p(y)
$$

`p(y)` 是学生给真实类别的概率，`log` 是自然对数。这个概率越大，CE 越小。例如真实类别为 E 时，把 `p(E)` 从 0.40 提高到 0.80，CE 就从约 0.916 降到 0.223。

真实标签告诉学生“应该选 E”。但如果两个学生都给 E 分配了 0.60，它们这一条样本的 CE 就相同，即使剩余 0.40 在其他三类上的分配差很多。

### 5.2 KL：学习四类概率之间的分配

**KL 用来衡量两组概率分配的差异。使用前，两边都应是概率分布：每个数非负，各自加起来等于 1，并且类别顺序一致。** 本项目两边都按 E、S、C、I 排列。

参考概率记作 `q`，学生当前预测记作 `p`。训练时减小 `KL(q ∥ p)`，就是让学生的四类概率接近参考概率；KL 不小于 0，完全一致时为 0。归一化在计算 KL 之前完成，本项目用 softmax 得到学生概率。

对应公式是：

$$
\mathrm{KL}(q\parallel p)
= \sum_{c\in\{E,S,C,I\}} q(c)\log\frac{q(c)}{p(c)}
$$

`c` 依次取四个类别，`q(c)` 和 `p(c)` 分别是参考与学生给这个类别的概率。公式先计算每个类别对应的一项，再把四项相加。整组概率越接近，KL 越小；完全相同时，KL 为 0。


### 5.3 三组如何组合两项损失

现在可以把第 4 节的学习要求写成公式。以下都是**一条样本**的损失：

| 组        | 损失                             | 含义                             |
| --------- | -------------------------------- | -------------------------------- |
| CE_CONT   | `CE(y,p)`                      | 只使用真实标签这一项             |
| REF_KD    | `(CE(y,p) + KL(p_S ∥ p)) / 2` | 平均真实标签损失和原模型参考损失 |
| FUSION_KD | `(CE(y,p) + KL(q ∥ p)) / 2`   | 平均真实标签损失和融合参考损失   |

后两组中，CE 和 KL 的系数都是 0.5，两项共同决定参数更新。这里的“各占一半”指公式系数，实际损失大小和梯度大小取决于当前预测。与 CE_CONT 相比，两个使用参考概率的组既增加了参考概率，也把 CE 系数从 1 调整为 0.5；因此，与 CE_CONT 的比较对应这套完整的损失设计。

训练时，学生算出 `p`，据此计算损失，再沿着损失的梯度更新自己的 LoRA 参数。`p_S` 和 `q` 是从文件读入的常数，底座原有权重保持固定。每次更新之后，会改变的是学生下一次给出的 `p`；作为参照的那四个数继续保持原值。

### 5.4 REF_KD 的设计理由：去掉教师后会怎样

第一阶段 SFT 的任务是让底座学习 ESCI 标签，本项目直接使用标签交叉熵。底座尚未经过这项任务的专门训练，保留它原有的四类判断是否有益，需要另行验证。第二阶段已经有任务模型 S，但这一点也只让它的输出成为一份有意义的参考；**REF_KD 的设计理由来自实验问题：在融合方法中移除教师，效果会怎样？**

因此要区分两件事：作为训练操作，它是带原模型输出约束的续训；作为实验设计，它是用来检验教师融合增量的消融组。它的价值在于提供可比较的参照，是否能提高成绩由结果决定。CE_CONT 则继续提供普通标签续训基线。

还可以从实际优化目标看清这个对照。把真实标签写成四维向量 `e_y`，例如真实类别为 E 时，`e_y = [1, 0, 0, 0]`。固定参考概率与学生之间的 KL，和使用该参考概率的交叉熵，只差一个与学生参数无关的常数。因此，在本轮温度为 1、CE/KL 等权的设置下，参数更新等价于学习下面的混合标签：

| 组与样本情况 | 参数更新所对应的混合标签 |
|---|---|
| CE_CONT | `e_y` |
| REF_KD：全部样本 | `0.5 × e_y + 0.5 × p_S` |
| FUSION_KD：实际融合教师的样本 | `0.5 × e_y + 0.25 × p_S + 0.25 × p_T` |
| FUSION_KD：其余样本 | `0.5 × e_y + 0.5 × p_S` |

这张表说明，融合组在选定样本上把原模型参考中的一半份额换成了教师概率；真实标签的权重保持一致，其他样本的监督规则也相同。REF_KD 因而控制了“有软目标、有原模型成分、CE/KL 权重相同”这些条件，让比较集中到**按既定路由和平均规则加入教师概率的效果**。表格是对优化目标的等价解释，实际代码仍按第 5.3 节计算 CE 和 KL。

如果只关注整套融合方法相对普通续训的表现，CE_CONT 与 FUSION_KD 已能回答这个问题；REF_KD 为结果增加一层来源分析。进一步区分教师的类别判断、置信度变化或概率平滑各自贡献多少，则需要针对这些因素另设对照。

相关文献可以帮助认识“保留旧输出”这种训练形式：例如 [Learning without Forgetting](https://arxiv.org/pdf/1606.09282) 用蒸馏损失保留旧任务输出；[DPO](https://arxiv.org/html/2305.18290v3) 研究带参考模型约束的偏好优化。这些方法解决的任务与本项目不同，本轮 REF_KD 的用途由上面的消融问题界定。

## 6. 怎样训练并选出最终模型

先区分几份数据的用途：

| 数据               | 查询数 / 样本数 | 在流程中的用途                     |
| ------------------ | --------------: | ---------------------------------- |
| pilot_train        |  1,024 / 20,941 | 第一阶段训练原模型 S               |
| posttraining/train |    512 / 10,398 | 本轮三组学生的参数更新             |
| tune               |     256 / 5,223 | 在训练过程中选择表现最好的模型存档 |
| gate               |    512 / 10,438 | 选好模型后评测                     |
| F                  |    512 / 10,459 | 选好模型后，在项目固定评测集上评测 |

数据按查询划分，准备时检查查询文本和样本身份的重叠。同一商品可能出现在不同划分里，因此这项评测主要观察模型对留出查询的表现。

**gate 和 F 来自两份不同的官方划分。** `pilot_train`、`tune` 和 `gate` 都从 ESCI 官方 train 划分中按查询抽取；其中 gate 的 512 个查询留作评测。F 则从官方 test 划分中抽取 512 个查询，形成项目固定使用的评测子集。数据来源可在本地 `data/final/manifest.json` 与 `data/sft/manifest.json` 中核对。

gate 的名称沿用早期试训流程：当时用它检查模型是否值得进入后续实验。本轮保留这份已有的开发检查集，用来观察同一批已选模型在另一批查询上的表现；F 提供官方 test 子集上的主要报告成绩。增加 gate 是本项目的补充检查安排，通常也可以用训练集、验证集和测试集组织实验。本轮的执行顺序是 **tune 选定模型 → 在 gate 和 F 上分别报告成绩**，代码没有设置“gate 达标后才允许评测 F”的步骤。

**gate 和 F 可以合并计算成绩。** 两者不重合，合并后共有 1,024 个查询、20,897 个商品对。在当前训练程序里，两者都用于选点后的评测；保留两个名称主要是为了区分来源和历史用途，并延续固定 F 的报告口径。

是否合并，取决于希望总分代表什么。分别报告，能看到官方 train 中的留出查询与官方 test 子集各自的表现；合并报告，则衡量这两批样本混合后的表现。不同来源本身不妨碍合并，但需要明确这个混合口径。已有结果若增加联合评测，可以另列 `gate ∪ F`，保留两个来源的分项成绩；Macro-F1 和区间应从合并样本重新计算。合并后的集合也延续原有的开发与评测使用历史。

本轮最多把 10,398 条训练样本完整学习两遍。每次参数更新通常合并 32 条样本，每遍最后剩 30 条，一遍共 325 次更新，两遍共 **650 次更新**。

训练过程中会保存模型存档，称为 **checkpoint**，并在 tune 上评测。这里用到的三个指标分别是：

| 指标     | 衡量什么                                                           |
| -------- | ------------------------------------------------------------------ |
| Accuracy | 所有样本里，类别预测正确的比例                                     |
| Macro-F1 | 先为每个类别计算兼顾查准率和查全率的 F1，再把四类等权平均          |
| nDCG@10  | 对每个查询，前十个商品的排序质量；越相关的商品排得越靠前，得分越高 |

三组按同一规则选存档：**tune Macro-F1 最高的优先；精确并列时比较 nDCG@10，再取更早的更新步。** 选好三组存档之后，再用它们评测 gate 和 F。

本轮三组都完成了 650 次更新。每组实际累计处理 `10,398 × 2 = 20,796` 条次的样本；同一条样本读两遍计两条次。最终选中的存档如下：

| 组        | 选中存档的更新步 | 到该存档为止累计处理的样本条次 | 完整运行的更新步 |
| --------- | ---------------: | -----------------------------: | ---------------: |
| CE_CONT   |              569 |                         18,206 |              650 |
| REF_KD    |              569 |                         18,206 |              650 |
| FUSION_KD |              488 |                         15,614 |              650 |

FUSION_KD 的最佳存档出现在更早的位置。实际运行仍然完成了后续更新和评测，所以本次三组使用了相同的更新次数；被选作最终模型的存档处于不同训练进度。

gate 的具体评测由 [fusion.py](../src/fusion.py) 的 `final_evaluation()` 完成，与 F 上四个单模型的评测采用相同方法：

1. 读取已经选定的三组 checkpoint，并加载原模型 S 作为共同起点参考；模型进入推理状态，参数保持固定。
2. 四个模型分别对 gate 的全部 10,438 条样本独立输出四类概率。分类取概率最大的类别；商品排序使用第 1 节的相关性分数。
3. 用真实标签计算 Accuracy、Macro-F1、每类 F1 和 nDCG@10。分类指标汇总全部商品对，排序指标先按查询计算再平均。
4. 在同一批查询上比较 FUSION_KD 与其余三个模型，做 10,000 次查询配对 Bootstrap，得到差值区间。

gate 的这些成绩来自单模型推理。F 的报告另外增加了 S_C50 融合系统和缓存教师作为参照。gate 和 F 都已在项目历史中查看过，承担的是既有数据上的检查与评测。

## 7. 最后学到了多少

在固定评测集 F 上，原模型 S 和三个续训学生使用同一运行环境重新评测。表中的融合系统用来参照“学生想学习的系统达到了什么水平”：

| 模型或系统                        |         Accuracy |         Macro-F1 |          nDCG@10 |
| --------------------------------- | ---------------: | ---------------: | ---------------: |
| 原模型 S                          |           54.83% |           47.50% |           0.7682 |
| CE_CONT：标签续训                 |           55.88% |           48.31% |           0.7658 |
| REF_KD：原模型约束对照                |           55.65% |           48.18% |           0.7671 |
| **FUSION_KD：融合蒸馏**     | **55.73%** | **49.22%** | **0.7698** |
| S_C50：原模型与教师的半量融合系统 |           57.15% |           52.08% |           0.7804 |

融合学生的 Macro-F1 高于两个续训对照，也高于原模型 S；它独立运行就能取得这个成绩。学生的 49.22% 与融合系统的 52.08% 之间仍有差距，说明本轮迁移了部分融合收益。

为了判断分数差异对评测查询的抽样是否敏感，报告还做了**查询配对 Bootstrap**：每次有放回地抽取一批完整查询，用同一批查询同时计算两个模型的成绩，再记录差值。重复 10,000 次，得到差值的 95% 区间。完整抽取一个查询，会保留该查询下各商品之间的关系。

| Macro-F1 比较         |           差值 |       95% 区间 |
| --------------------- | -------------: | -------------: |
| FUSION_KD − CE_CONT  | +0.91 个百分点 | [+0.11, +1.74] |
| FUSION_KD − REF_KD   | +1.04 个百分点 | [+0.40, +1.73] |
| FUSION_KD − 原模型 S | +1.72 个百分点 | [+0.79, +2.72] |

这三项区间都在零以上，支持本次实验中融合学生的 Macro-F1 改善。其中，与 REF_KD 的比较支持把原模型参考换成融合参考的做法；与原模型 S 的差值则包含了本轮继续训练带来的整体变化。

其他指标的证据较弱：相对两个续训对照，Accuracy 和 nDCG@10 的差值区间都包含零，当前抽样结果同时容许正差值和负差值。另一个评测划分 gate 上，融合学生相对 REF_KD 的 Macro-F1 差值为 +0.76 个百分点，区间为 [−0.06, +1.56]，也包含零。

这份结果的范围是**当前配方、一个训练随机种子和既有评测集**。Bootstrap 描述已训练好模型在查询抽样下的差异；重新训练产生的波动需要多次训练来评估。F 已在此前项目迭代中查看过，本轮用 tune 选存档，F 提供既有固定集合上的评测证据。以上区间为单项区间，未作多重比较校正。完整的逐类成绩与区间见[实验报告](../results/fusion_continue_20261021/RESULT.md)。

## 8. 前面的过程在代码里怎样实现

### 8.1 从输入得到四类概率

[common.py](../src/common.py) 的 `encode()` 把查询、标题、品牌放进固定提示，并调用模型的聊天模板。[modeling.py](../src/modeling.py) 随后完成从输入到概率的计算：

1. Qwen 主体网络处理输入，得到每个位置的隐藏表示。
2. 取最后一个有效输入位置的表示，作为预测下一个标签的依据。
3. 从模型原有的词表输出层（LM head）中，取 E、S、C、I 对应的四行权重，算出四个原始分数，称为 logits。
4. 对这四个分数做 softmax，得到总和为 1 的四类概率。

其中 `RelevanceModel.forward()` 完成前三步，推理函数 `infer()` 完成第四步；训练时由损失函数计算对应的对数概率。

这要求四个标签在 tokenizer 中各对应一个 token，程序会检查这一点。LoRA 安装在注意力和 MLP 的投影层中，rank 为 16、alpha 为 32；训练通过更新这些附加参数改变模型的隐藏表示，从而改变最终四类概率。

这里是**同一个待预测位置上的四个不同标签 token**。代码只对 E、S、C、I 的四个分数做 softmax，得到加起来为 1 的四类概率，再与同样归一化的参考概率计算 KL。它表达的是“答案限定为这四类时，各类应占多少概率”，与本项目的分类和排序用途对应。

### 8.2 从缓存读出参考概率，再计算损失

[fusion.py](../src/fusion.py) 的 `prepare()` 按第 3 节规则准备融合参考。路由只依据原模型置信度，置信度并列时用样本 ID 的固定哈希值决定先后。它为每条训练样本保存两列概率：

| 文件字段                    | 对应前文符号       | 哪一组用它计算 KL |
| --------------------------- | ------------------ | ----------------- |
| `reference_probabilities` | 原模型概率 `p_S` | REF_KD            |
| `fusion_probabilities`    | 融合参考概率 `q` | FUSION_KD         |

[fusion.py](../src/fusion.py) 先读取 `targets.jsonl`：这是每行一个 JSON 对象的文本文件。JSON 解析后成为 Python 字典；程序从每条记录中取出所需的概率字段，按固定的 E、S、C、I 顺序排列，再用 `torch.tensor(..., dtype=torch.float32, device='cuda')` 转成可在 GPU 上计算的数值数组，也就是张量。

例如，第 3 节的融合概率在文件中的字段是：

```json
{"fusion_probabilities": {"E": 0.60, "S": 0.225, "C": 0.10, "I": 0.075}}
```

取出并排列后，这条样本对应张量中的一行 `[0.60, 0.225, 0.10, 0.075]`。这是把已经算好的概率换成便于数值计算的存储形式，数值精度使用 FP32；这里也不用 tokenizer，文本输入的编码是另一条处理流程。

全部 10,398 条记录先组成形状为 `[10398, 4]` 的 `targets` 张量；训练时再按本次处理的样本索引取出几行，传给损失函数的 `target` 参数。因此，**`target` 是当前小批样本的参考概率表**，形状为 `[小批样本数, 4]`。正常每次处理 4 条，就是 `[4, 4]`；末批最后剩 2 条时，就是 `[2, 4]`。

`fusion.loss_rows()` 的核心代码与第 5 节公式一一对应：

```python
# logits：学生的四类原始分数；labels：真实类别；target：四类参考概率
logp = F.log_softmax(logits.float(), dim=-1)  # 学生各类概率的自然对数
ce = F.nll_loss(logp, labels, reduction='none')  # 每条样本的 -log p(y)
kl = F.kl_div(logp, target.float(), reduction='none').sum(-1)
loss = ce if arm == 'CE_CONT' else (ce + weight * kl) / (1 + weight)
```

这里 `F` 是 `torch.nn.functional` 的代码别名，与评测集 F 按上下文区分。`kl_div` 接收的第一个参数是**学生概率的对数**，第二个参数是**参考概率本身**。它计算的是 `target × (log(target) − logp)`；随后 `.sum(-1)` 把四个类别相加，得到每条样本的 `KL(target ∥ p)`。因此 REF_KD 对应 `KL(p_S ∥ p)`，FUSION_KD 对应 `KL(q ∥ p)`。

本轮 `weight = 1`，所以后两组损失是 `(ce + kl) / 2`。配置中的温度为 1，即直接使用上述概率。对数概率和损失使用 FP32 计算。

### 8.3 一次更新怎样合并多条样本

显存里每次处理 4 条样本，这叫 micro batch；通常累计处理 32 条后，优化器才更新一次参数。程序对每一小批执行 `loss.sum() / 本次更新的实际样本数` 再反向传播，多次累积后，得到这一整批样本平均损失的梯度。

10,398 除以 32 后，最后一批剩 30 条。这次更新的分母就是 30，让末批仍然按每条样本的平均损失来更新。这个细节影响批次如何平均，三组各自的单样本损失仍是第 5 节的公式。

训练设置保存在 [fusion_continue_20261021.json](../configs/fusion_continue_20261021.json)：优化器为 AdamW；学习率先用 33 步逐渐升到 `2e-5`，再按余弦曲线降到第 650 步的 `2e-6`；随机种子为 20261001，dropout 为 0。训练在第 0、82、163、244、325、407、488、569、650 步进行 tune 评测。本轮三组均跑满预算，配置中的早停条件未触发。
