# S 检查点验收方案

日期：2026-10-19。状态：**保留为 S 起点设计的讨论记录，尚未接入训练代码，也尚未执行。下一轮已转为 [底座直训三组](底座直训三组执行计划_20261019.md)，不再以本方案验收公共 S。** 本方案中的数值是待标定的工程目标，不是行业标准或已验证的性能上限。历史结果已知，因此不能称为历史实验的预注册门槛。

## 为什么需要修改

当前流程确实是 Qwen3-0.6B → ESCI 标签交叉熵 SFT（LoRA，r=16、alpha=32，底座冻结）→ S → 从同一个 S 分别训练 A2/TA2/G2。

`src/train.py::train_sft` 固定训练两轮，仅在轮末评估 tune，以 Macro-F1、nDCG@10、较早轮次的顺序选点。它没有判断是否进入平台期，也没有在后训练前执行质量验收。

历史初筛要求 Macro-F1 ≥45%、S/C recall ≥15% 等，目标是判断是否值得继续投入。历史 Qwen 的 tune Macro-F1 从第 1 轮 45.26% 升至第 2 轮 47.59%，accuracy 从 52.79% 升至 55.73%。这说明两轮内仍有提升，**不能据此判断两轮之后仍必然提升，也不能宣称已经训练充分**。

证据：旧门槛（本地文件 `_archive/20260930_legacy_workspace/esci_training/gate_rules.json`，未随仓库发布）、历史曲线及 gate 结果（本地文件 `_archive/20260930_legacy_workspace/esci_training/PILOT_REPORT.md`，未随仓库发布）。

## 两种基线必须区分

- B：未做本项目 SFT 的底座。B0 使用与 S 完全一致的输入、四标签打分及精度；可另加入事先固定的提示基线，用 tune 选择一个 Bprompt。S 必须分别与 B0 和 Bprompt 比较，不能只挑较弱者；不做提示对照时须明确结论只覆盖 B0。
- S：完成任务适配后的公共训练起点，也是后训练的基线。S 应通过本节的验收，之后仍需要 A2/G2 等同预算对照检验后训练价值。

如果 B 已达到绝对质量线，既可能表示底座能力较强，也可能表示门槛偏低；没有业务要求和独立标定，不能仅据此认定底座已经足够好或 SFT 没有必要。应先说明门槛依据，并结合相对收益判断。可以在开发阶段修订目标、另立协议版本，但不能把看过同一结果后修改的门槛当作事先确定的确认性标准。若 S 通过验收，它只是建立了后训练所需要的起点，并不表示后训练研究已经结束。

## S 的质量验收：全部满足

以下提出一个比旧初筛更严格、可直接执行的新版本。百分数差值均指百分点；例如 +5 个百分点对应指标差 +0.05。

| 维度 | 建议门槛 | 目的 |
|---|---|---|
| 总体质量 | Macro-F1 ≥50%，accuracy ≥55% | 两项同时过线，不靠偏向多数类获得表面高分 |
| 实际适配收益 | 对每个已声明的 B：Macro-F1 提升 ≥5 个百分点，accuracy 提升 ≥2 个百分点；两项查询配对 95% 区间下界均 >0 | 既要求有实际幅度，也要求有统计证据 |
| 类别完整性 | E/S/C/I 每类 F1 ≥30%，每类 recall ≥25% | 防止牺牲某个类别，尤其是 C 类 |
| 工程有效性 | 数据隔离、输入/模型身份、概率合法、有限损失/梯度、实际训练预算全部核验通过 | 排除数据泄漏和实现故障 |

在 gate 上判定，保留完整混淆矩阵、每类 support/precision/recall/F1、NLL 和 nDCG@10。总体绝对线和类别线采用点估计；相对收益另加区间要求。Bootstrap 以完整查询为配对单位，2,000 次，seed=20260930。所有比较完整输出，不把“accuracy 或 Macro-F1 随便一项显著”作为通过规则。

这些绝对数值暂未得到业务成本函数或独立样本标定，不能承诺此数据量、输入字段和模型容量一定可达。历史 S 的 gate Macro-F1=47.81%、accuracy=53.65%，按新目标会未通过；这只能表示新目标更高，不能倒推旧实验无效。**不得用历史 F 的 54.99%/47.63% 代替 gate 验收，更不能从最终 F 反推门槛。**

## 训练是否足够：单独判断

“过线”与“训练充分”是两个条件。过线但仍明显进步，不宜立即把 S 冻结成强基线；进入平台但未过线，也不能算合格。

建议新 SFT 配方采用：

1. 最少 2、最多 6 epochs，每半轮评估一次 tune，保留逐次预测、NLL、两项分类指标和候选 adapter。训练上限约 3,954 optimizer steps；这是上限，不是必须跑满的目标。
2. 学习率调度从运行开始就按 6 轮上限定义，建议 warmup 后 cosine 到峰值的 10%，不用当前两轮结束归零的调度来证明平台。保持数据、LoRA、batch 与其余超参数固定，明确记录这是新配方。
3. 每次检查最近连续 4 个评估点（约 2 轮）：相对于该窗口开始前各指标的历史最好值，窗口内任何点的 Macro-F1 和 accuracy 增益都不足 0.5 个百分点，才满足操作性的停止条件。比较窗口前最好值，避免把每次增加 0.3、累计增加 1.2 个百分点误判为没有进步。
4. checkpoint 仍按现有 tune 规则选取：Macro-F1 最大，精确并列时比较 nDCG@10，再取更早 checkpoint。accuracy 与 NLL 全程报告；不根据 gate 换另一个 checkpoint。若 NLL 持续上升，报告过拟合迹象并保留 tune 选中的较早权重。
5. 达到预算上限仍未满足停止条件，状态记为 `BUDGET_EXHAUSTED`，不能写“已收敛”。满足停止条件只能说“在该数据、优化配方及预算内达到操作性平台”，不能声称全局最优。

早停是开发规则，不是显著性检验。特别是“继续训练的收益区间跨 0”不等于收益小于 0.5 个百分点。若要提出更强的饱和结论，应事先固定一次额外 CE 训练探测和独立确认数据，要求其收益的区间上界低于预设的实际重要性界值；当前 256-query tune 的统计精度可能不足，证据不足时须保留“不确定”。本方案不把反复查询 tune 的 bootstrap 包装成独立确认。

## 验收集和失败处理

当前数据按查询隔离：SFT 1,024 查询 / 20,941 对；tune 256 / 5,223；gate 512 / 10,438；另有后训练集及最终 F。

- tune 用于训练停止和 checkpoint 选择。
- gate 在候选 S 冻结后用于质量判定。当前 gate 已被历史试训、错误审查使用，只能称为开发验收集；历史 F 也不是新独立测试集。
- 若需要新的确认性结论，在下一轮前从尚未使用的数据中固定新的查询级留出集，检查 query ID、规范化查询文本和 example ID 与所有训练、开发、历史评测数据隔离。不能把旧 gate 换名字冒充新测试集。
- gate 未通过，保留失败记录，不按 gate 反复改超参数、换 checkpoint 直至通过。修改协议必须另起版本；已用于反馈的集合继续视为开发数据。

状态至少分为 `PASS`（停止条件与质量条件都满足）、`QUALITY_FAIL`（质量未达标）、`BUDGET_EXHAUSTED`（停止条件未满足且预算耗尽）、`INVALID`（输入或训练故障）；报告各条件的布尔值，允许同时存在多个失败原因。只有 `PASS` 才按这个 S 起点方案自动进入三个后训练实验组，其余状态停止流水线并保存产物。

## 后训练是否值得：不能用 S 的验收线代替

后训练要比较在同一个 S、相同数据、更新数和选择规则下的增量收益：

- TA2 对 A2：教师监督是否优于标签监督加冻结 S 的 KL 约束。
- TA2 对 G2：教师软概率是否优于同样被选中的样本上额外标签监督。
- 如要主张“收益并非只是普通 SFT 继续训练即可获得”，新增同预算纯 CE 续训对照 C2；A2 含 KL 约束，不能直接代替纯 CE。后训练使用了另一批查询，其收益也不能简单归因为原 S 的训练轮数不足。

建议将“有实际价值的后训练改进”另外定义为：相对每个所声称胜出的对照，两项分类指标至少一项提升 ≥0.5 个百分点且获得正向证据；另一项的区间下界不得低于 −0.5 个百分点。若运行后在两项中择优宣称提升，须对预先列出的对照与指标做多重比较校正（例如 Holm，整体 α=0.05）；未校正区间仍可全部展示，但不当作整体确认性结论。更简单的做法是在新运行前固定唯一主要假设，两项指标仍并列完整报告。

该建议比当前历史报告的点估计/逐项区间展示更严格，是未来实验的决策规则，不追认历史结果已经通过。若需要声称跨训练随机性稳定，应预设并报告多 seed 的整套实验，不能靠查询 bootstrap 替代；本方案尚未执行这些扩展实验。
