# 历史实验（2026-10-20）：缓存子集三组直训

该轮日期：2026-10-20。当时入口是 `src/train_subset.py`，配置为 `configs/training_subset_20261020.json`。旧 S→A2/TA2/G2 续训和 31,339 条合并直训均保留作历史实验。

## 三组、数据与损失

CE、KD、WCE 从同一个官方底座及同一份未训练 LoRA 开始。只用 `data/posttraining/train.jsonl` 的 **10,398 条 / 512 查询**更新参数，不使用另 20,941 条 `pilot_train`，不从旧 S 或第 980 步模型开始。

| 组 | 逐样本目标 |
|---|---|
| CE | `CE(y,p)` |
| KD | `CE(y,p) + c*m*KL(T||p)` |
| WCE | `CE(y,p) + c*m*CE(y,p)` |

`c=10387/5467≈1.899945`。已有教师缓存中 10,387 条有效，5,467 条答对；只有答对样本 `m=1`。缓存可在每轮重复使用，新增 DeepSeek 请求为 0。三组均无 `KL(S||p)`，也没有到未训练底座的 KL。损失实现是 `direct_subset.objective()`；`modeling.py` 的旧续训损失不被本轮调用。

共同初始化和按 `seed+epoch` 生成的样本顺序已实现。LoRA r=16、alpha=32、dropout=0.05；effective batch=32、microbatch=16，尾批 30 条按实际条数归一化。代码没有在每组首次训练前统一重置 dropout RNG，因此不能声称三组共享逐步相同的 dropout 随机掩码。

## 975 是预算，最佳 checkpoint 由 tune 决定

当前配置每轮 325 步、共 3 轮，即每组执行 975 次更新；warmup 49 步，峰值学习率 1e-4，cosine 调度终点为 1e-5。**975 来自预算选择，没有证据表明它是最佳训练时长。** 调度长度也固定为 975，改变训练上限会改变整个学习率过程。

评估位置为 `0、163、325、488、650、813、975`。每组独立按 tune Macro-F1 最高选点，平局看 tune nDCG@10，再平局选更早步。975 步结果仅作固定预算补充；三组平均 tune 分数选出的共同步数也只作补充，不替代逐组选点。gate/F 不参与 checkpoint 选择。

**实现限制：当前 `train_all()` 会跑满 975；平台期统计没有触发提前停止。** `verify_recipe()` 也固定要求三轮。若“挑最好点”指交付 checkpoint，当前训练已支持；若还指取消固定三轮或按平台期提前停止，当前实现尚未包含这一改变。

2026-10-20 对执行主机 `runs/subset_direct_20261020/selection.json` 和曲线的只读快照显示：

| 组 | tune 选中步 | 选中点 tune Macro-F1 | 第 975 步 tune Macro-F1 |
|---|---:|---:|---:|
| CE | 488 | 45.50% | 45.12% |
| KD | 488 | 47.83% | 45.95% |
| WCE | 488 | 47.29% | 45.81% |

这是已评估位置中的最优点，不证明未评估步数中不存在更好模型。三组平均分的共同最优点这次也为 488，所以两种规则恰好一致。

后续已收到完整产物，`execution_receipt.json` 状态为 complete，本地离线复算通过。F 上 CE/KD/WCE 的 Macro-F1 分别为 46.40% / 46.67% / 47.12%，并未改善合并数据直训的对应结果。详见 本轮结果（本地文件 `runs/subset_direct_20261020/RESULT.md`，未随仓库发布） 和 降分诊断（本地文件 `results/diagnostics/subset_direct_20261020/降分诊断.md`，未随仓库发布）。此处没有追加训练。

## 入口与输出

在项目根目录做 CPU 输入检查：

```powershell
python src/train_subset.py --check-only
```

复现本次固定三轮配方时使用新的输出目录；下列命令不是要求重启正在运行的作业：

```powershell
python src/train_subset.py --config configs/training_subset_20261020.json --output runs/subset_new
```

`--resume` 用于同一作业从已保存评估位置恢复模型、优化器、调度器与 RNG；这里的“恢复”不等于历史 S→A2/TA2/G2 续训。`--evaluate-only` 从已训练状态完成评测，不更新模型。两者均需要 GPU 主机上完整状态及相同输入/配置。

完成训练和评测后用 `python src/analyze_subset.py --run <作业目录>` 离线复算。报告以各组 tune 选中的模型为主，保留固定 975 步和已有共同步数预测的补充结果。当前轮没有融合训练组；B0、T 是评测参考对象，不计入三组。

运行目录保存 `protocol/`、`learning_curves.json`、`selection.json`、`states/`、`predictions/`、验证记录和报告。历史源码身份以运行时 `protocol/source_hashes.json` 为准；本次本地说明与报告修订不会改变已运行模型。
