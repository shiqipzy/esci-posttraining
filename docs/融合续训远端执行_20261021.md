## 目标与可解释性

唯一优化目标是把已经成立的 S + DeepSeek 半量融合收益迁移进独立推理的学生。S 是官方 Qwen3-0.6B 经 ESCI CE LoRA SFT 得到的现有任务模型，不是凭空增加的研究阶段。其作用是提供已有可用的本地任务模型和固定系统输出。本轮不重训 S、不重新立项证明互补，不把 S 当作经过新验收的最优模型。

按后续讨论，本轮采用已有 S 的 LoRA 作为三组共同起点，继续更新同一 adapter；每组重置优化器和随机数状态。该选择替代最初“官方底座 + 未训练 LoRA”的初始化要求。它检验的是任务 SFT 后的第二阶段改进，不能据此声称比直接从官方底座蒸馏更好；本轮不增加训练组去回答后一个问题。

S 身份：`models/S/adapter/adapter_model.safetensors`，SHA256 `96c5ccc5ea9775f5da50ad25701cc8b2b0235b00b5e73943e2d0dff1ed2752da`。原选择来自 CE epoch-2；第一阶段 20,941 条仅是来源说明，本轮不会再次使用。

官方底座：Qwen/Qwen3-0.6B，revision `c1899de289a04d12100db370d81485cdf75e47ca`；按 `configs/models.lock.json` 核对所有必要文件。

## 固定监督数据流和三组

原模型软蒸馏就是把冻结 S 的 E/S/C/I 概率当作软目标。它用于检验“保留原模型行为”的效果，并不需要再训练一个监督模型。

| 组 | 更新起点 | 每条样本损失 | 作用 |
|---|---|---|---|
| CE_CONT | 同一 S adapter | CE(y,p) | 相同数据、初始化与训练控制下的纯标签续训 |
| REF_KD | 同一 S adapter | [CE(y,p)+KL(p_S‖p)]/2 | 固定原模型软目标对照 |
| FUSION_KD | 同一 S adapter | [CE(y,p)+KL(q‖p)]/2 | 蒸馏已有融合系统的完整输出 |

温度 T=1，软监督系数 λ=1；两软监督组完全相同的覆盖、归一化和训练控制。KL 对四类求和，随后对实际有效 batch 的样本求平均。尾 batch 为 30，按 30 归一化。log-softmax 和 loss 使用 FP32。零概率按 0 log 0=0 处理。

q=(p_S+p_T)/2，仅用于按 max(p_S) 从低到高选择的 5,199 条里教师有效的 5,195 条；其他 5,203 条 q=p_S。相同置信度按 SHA256(`esci-cascade-v13|example_id`) 排序。路由与目标数值不读取标签或教师正确性。训练 CE 部分使用标签，不能把这误写为全流程无标签。

全部 10,398 条、512 查询都计算蒸馏损失；11 条教师失败直接回退 p_S，其中 4 条位于路由范围。没有正确性门控、旧权重 10387/5467、额外原模型 KL 或 80/20 标签平滑。目标不会随新学生更新，CE_CONT 不参与监督来源。

比较 FUSION_KD−CE_CONT 判断这种融合蒸馏是否改善相同预算策略下的续训学生；FUSION_KD−REF_KD 隔离在原模型软目标中加入教师互补信息的增益。同时比较 FUSION_KD−初始 S，防止把“比退化的 CE 更好”写成绝对提升。初始 S 只做评测，不新增训练组。

## 训练、选点与停止

配置 `configs/fusion_continue_20261021.json`，现对应入口 `python src/train.py fusion`，实现位于 `src/fusion.py`。只训练 S 既有 LoRA，r16/alpha32/原 target modules；实际 dropout=0 并同步保存到 adapter 配置。BF16 backbone，SDPA，关闭 TF32，关闭 gradient checkpointing；effective batch32、microbatch4。

AdamW，weight_decay=.01，梯度裁剪1。峰值 LR=2e-5，是既有 SFT LR1e-4 的五分之一，作为保守续训起点；33步线性 warmup，随后 cosine 到650步的2e-6，不重启优化器。λ=1 是单一预注册起点，用于均衡真实标签与固定软目标，不宣称已调优。

seed=20261001；每组独立重置 RNG；epoch e 使用 seed+e 排序，两个 epoch 的顺序哈希记入清单。每个完整 epoch325步、10,398行；最多2个epoch/650步。不将975、980或650预设为最优步。

tune 在0、82、163、244、325、407、488、569、650步评测。至少完成325步；之后若连续4个评测点未比上一次有意义改善的基准提高 Macro-F1≥.001，则停止。小幅改善累计达到.001会重置计数。早停阈值只控制停止；最佳 checkpoint 总是选择实际最高 tune Macro-F1，完全并列再取较高nDCG@10、再取更早步。step0允许被选中，表示没有可选的更好续训点。

每组独立选点，记录选中/停止步数与行曝光量；因此比较的是相同预算上限和选择策略，不声称各最佳 checkpoint 曝光量完全一致。每个评测点保存模型、优化器、RNG和历史；中断从最近完整评测点恢复，最多重复一段未保存训练，不改变已完成前缀。恢复时必须代码、数据、配置和运行环境一致。

## 评测与结论边界

所有学生和 S 使用相同 prompt、tokenizer、右 padding、max_length512、enable_thinking=False、BF16、SDPA、batch8。超过512直接报错，没有隐式截断。历史跨轮曾出现不同 batch/机器的概率差异，原因尚未完全定位，因此不直接将旧 S 数字与新学生相减；新流程同环境重评 S。训练目标仍冻结为已有正确 S 缓存，不自动替换为重评概率。

先冻结三组 tune 选点，再评 gate 与 F。accuracy、Macro-F1并列，补充每类 F1与nDCG@10，gains=1/.1/.01/0。按查询配对 bootstrap10,000次、seed20260930；分类指标对抽中的全部商品对重新聚合，nDCG对有效查询平均。给出三项主比较的差值及95%百分位区间。跨零代表证据不足，不代表等价；单seed区间不涵盖训练随机性，多指标不作为独立重复验证。

F 已反复查看，只是探索性确认集合；禁止用于超参或选点，不能包装成新的独立测试集。历史融合基准只作参照；在同一新 S 推理输出上还会复算 S_C50 以显示当前条件下的系统参考，绝不替代学生独立推理成绩。

- 成功：在事先固定的报告规则下，融合学生相对 CE、REF_KD、起始 S 有一致的实际收益；例如 Macro-F1 三个差值区间均为正，accuracy 无明确退化，再分别陈述每项指标证据。accuracy“不显著变差”不是已证非劣效。单轮结果仍限定于本配方和seed。
- 部分成功：只胜 CE、不胜 REF_KD，说明尚不能把收益归于教师互补信息；胜两个续训对照但未胜 S，说明减少退化而未完成绝对提升；只改善一种指标，明确说明指标权衡。
- 失败或证据不足：融合学生无可靠增益或有明显退化，只能否定/未支持本预算、初始化与loss下的迁移效果，不能推翻已有推理互补，也不能断言其他蒸馏做不到。

## 远端执行

独立目录：`/root/autodl-tmp/ESCI_fusion_20261021`。复用经哈希核对的 `/root/autodl-tmp/ESCI/models/base`，不覆盖旧实验。

```bash
cd /root/autodl-tmp/ESCI_fusion_20261021
bash scripts/fusion_preflight.sh                  # CPU预检，不训练
bash scripts/fusion_preflight.sh --gpu-check      # GPU前向检查，不更新参数
nohup bash scripts/fusion_run.sh > fusion_console.log 2>&1 < /dev/null &
tail -f fusion_console.log
```

训练启动命令会做GPU前向检查，通过后依次训练三组并评测。缺CUDA直接退出，不会转CPU训练。`flock`避免重复启动同一作业；再次执行同一命令会从最近完整checkpoint恢复。训练期间不可更换镜像、依赖、GPU型号或修改代码/配置，恢复时会校验。

结果：`runs/fusion_continue_20261021/evaluation/RESULT.md` 与 `report.json`；每组 `selected.json` 和 `updates_*.jsonl` 保留选点、曝光和损失记录。仅取报告和预测可执行：

```bash
tar -czf fusion_results.tgz fusion_console.log runs/fusion_continue_20261021/run_manifest.json runs/fusion_continue_20261021/selected_all.json runs/fusion_continue_20261021/*/selected.json runs/fusion_continue_20261021/*/updates_*.jsonl runs/fusion_continue_20261021/evaluation
```

执行前仅剩外部运行条件：启用可用的CUDA BF16 GPU并确认其显存能通过前向/训练首步；建议24GB或以上。所有研究参数已给默认值，无需再问一轮。GPU尚不可用时，上传/CPU检查成功不等于GPU可运行，更不等于迁移成功。
